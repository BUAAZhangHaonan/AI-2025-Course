# DeepCrack训练指南

## 📊 数据集特点

- **训练样本**: 300张图像
- **测试样本**: 237张图像
- **任务类型**: 二分类（裂缝/背景）
- **任务复杂度**: 相对简单

## ⚙️ 优化后的训练参数

### 针对小数据集的优化

| 参数 | 原始值 | 优化值 | 原因 |
|------|--------|--------|------|
| **最大迭代次数** | 40,000 | 5,000 | 小数据集容易过拟合，减少迭代次数 |
| **验证间隔** | 4,000 | 500 | 更频繁验证，及时发现过拟合 |
| **检查点保存间隔** | 4,000 | 500 | 更频繁保存，不错过最佳模型 |
| **批次大小** | 16 | 8 | 适应小数据集，每个epoch更多步数 |
| **日志间隔** | 50 | 20 | 更频繁记录，便于监控 |
| **工作进程数** | 8 | 4 | 减少资源消耗 |

### 训练周期计算

- 每个epoch步数: 300 / 8 = 37.5 ≈ 38步
- 总epoch数: 5000 / 38 ≈ 132 epochs
- 验证频率: 每500步 ≈ 每13 epochs验证一次

## 📈 监控训练

### 1. 关键指标

- **loss**: 应该持续下降，但不要降到接近0（可能过拟合）
- **decode.acc_seg**: 训练准确率，不应该长期保持100%
- **mIoU**: 验证集IoU，最重要的指标
- **学习率**: 应该平滑衰减

### 2. 过拟合判断

**当前训练显示的过拟合迹象：**
- ✗ 训练loss = 0.0002（过低）
- ✗ 训练准确率 = 100%（过高）
- ✗ decode.loss_ce = 0.0000（解码头损失为0）

**健康的训练应该：**
- ✓ 训练loss在0.01-0.1之间
- ✓ 训练准确率在90-98%之间
- ✓ 验证mIoU > 0.7

### 3. 何时停止训练

**提前停止条件：**
1. 验证mIoU连续3次不再提升
2. 训练loss降到0.001以下且不再变化
3. 训练准确率达到100%并保持

**预期训练时间：**
- 5000次迭代 × 0.58秒/次 ≈ 48分钟

## 🛠️ 故障排查

### 问题1: 训练loss过低（< 0.001）

**原因**: 严重过拟合
**解决方案**:
- 减少训练迭代次数
- 增加数据增强
- 使用Dropout

### 问题2: 验证mIoU很低（< 0.5）

**原因**: 模型没有学到有效特征
**解决方案**:
- 检查数据标注
- 增加训练时间
- 调整学习率

### 问题3: 显存不足

**解决方案**:
```bash
# 减小批次大小
python train_deepcrack_optimized.py --batch-size 4
```
